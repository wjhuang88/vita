# Change Control

Use when scope or architecture changes after implementation/iteration begins.

1. State the new request and why it cannot wait.
2. Identify affected acceptance criteria, dependencies, risks and published iteration baseline.
3. Classify the change: clarification, scope increase, replacement, urgent defect, or decision change.
4. If an ADR is contradicted, update/supersede the ADR before implementation.
5. Amend the iteration without erasing its original baseline; record added/removed work explicitly.
6. Synchronize backlog owners and then the board.
