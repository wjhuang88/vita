# Requirement Intake

1. Capture the outcome, receiver/actor and why it matters.
2. Classify each constraint as Hard, Soft or Assumption.
3. If the outcome spans independently testable slices, create an Epic and child Stories/Spikes.
4. Behavior-facing work uses Given/When/Then acceptance; technical/governance work uses equivalent observable evidence.
5. Record scope, exclusions, dependencies, minimum validation, state owners and uncertainty.
6. Link any governing ADR and state its implementation constraint.
7. Keep unresolved architecture questions as Spikes; do not let an assumption masquerade as a decision.
8. Add ready work to `docs/backlog/PRODUCT-BACKLOG.md`; detail lives in `docs/backlog/active/`.

Ready means the work is bounded, dependencies are satisfiable, acceptance is observable and required decisions are linked.
