# Vita 操作系统主界面：TUI、Agent 与系统配置研究

日期：2026-11-18。状态：**研究建议，未批准为架构决策或实现基线**。
范围：日常交互、首次启动、模型配置、基本 OS 管理、权限与恢复，以及可执行验证路线。
依据：Vita 当前分支基于 `07c45f3`；Talos 源码依据锁定版本 `261602242e49e6f921f5d3e4eac96eebbe92f8b3`，不代表 Talos 最新主分支。
研究完成不等于功能实现。未变更镜像、网络、凭据或系统配置。

## 1. 结论

建议实现 **Vita 自有 Rust 系统会话界面**：Agent 对话为主要入口，确定性的设置、状态和任务面板与它并列；两者共享同一套类型化能力和权限策略。基本设置必须在无网络、无模型、无密钥时可操作。

TUI 能承担这个界面，但 TUI 是呈现层，不应承担持久化、提权或系统服务生命周期。Talos Runtime 负责对话/规划/工具编排，Vita 负责真实系统状态、配置事务、目标身份和权限执行。一个“设置网络”的按钮不能绕过 Agent 工具同样必须遵守的 Broker 边界。

先交付宿主终端连接 VM 的全屏 TUI，验证控制终端和系统配置闭环；实体机中文输入/显示应独立验证。若纯 Linux VT 无法满足中文体验，可在后续采用最小图形终端会话承载同一 TUI，不必先建设完整桌面。

## 3. 产品范围：主界面应能做什么

| 区域 | 用户可见能力 | 不依赖模型的路径 | 优先级/边界 |
| --- | --- | --- | --- |
| 会话 | 多行输入、流式回答、任务列表、取消、会话恢复 | 切换/关闭任务、查看结构化结果 | 第一批；后台任务不能阻塞输入 |
| 系统首页 | 设备、启动模式、CPU/内存、电池/温度（可用时）、挂载、网络、服务健康 | 只读状态页、刷新、错误解释 | 第一批；缺失能力显示“未提供”而非正常 |
| 模型接入 | 协议、服务地址、模型、凭据来源、超时、推理参数、工具/图片能力 | 向导、连接测试、手动切换、撤销 | 第一批；未验证能力不得显示已支持 |
| 网络 | 有线、Wi-Fi、DNS、代理、静态地址、断开/重连 | 状态、扫描、密码输入、应用确认 | 首先有线/DNS，再 Wi-Fi；无线驱动/认证服务单独交付 |
| 本机偏好 | 语言、键盘布局、时区、字体/主题、辅助显示 | 本地表单和预览 | 首批键盘/时区；字体/IME受显示后端约束 |
| 时间 | 当前时间、时区、同步状态、手动校时/NTP配置 | 离线校时、诊断 TLS 时间错误 | 区分时区显示与修改系统时钟；后者需特权确认 |
| 服务与任务 | 服务状态、重启、依赖、日志、长期操作进度 | 本地操作和失败原因 | 依赖最终 supervisor；不假设存在 systemctl |
| 数据与持久化 | 临时/持久状态标识、解锁用户区、配额、导出/备份 | 明确选择存储目标、只读预览 | 先会话临时，后加密持久化；禁止默认写宿主磁盘 |
| 存储/用户镜像 | 源 USB 与目标盘识别、ISO 导入/校验、挂载管理 | 列表、目标确认、复制进度 | 格式化/安装不列入首批；P1/P3 边界保持独立 |
| 安全 | 会话锁定、凭据更换、审计、信任/远程入口状态 | 认证和授权面板 | 锁屏需要可信认证后端；隐藏文本不等于认证 |
| 更新/恢复 | 版本、签名/校验、空间、更新计划、回滚 | 本地恢复与故障诊断 | 完整性链/版本回退机制尚待设计；高风险单独验收 |
| 电源 | 重启、关机、可用的休眠/挂起能力 | 待完成任务提示、明确确认 | 先正常关机/重启；不自动启用依赖写盘的休眠 |

“包括系统配置”不等于首版实现全表。所有不可用项显示原因和前置条件，不绘制无效开关；不把任意 TOML 编辑器当产品设置页。

## 4. 信息架构与操作流程

建议顶层区域：**会话 / 系统 / 设置 / 任务与审批 / 帮助与恢复**。
全局状态条标明：当前机器/VM身份、会话用户、网络、所选模型、配置是否临时、待审批数量。
提供键盘导航、搜索设置项和命令面板；具体快捷键在终端验证后冻结，不能依赖鼠标或复杂组合键。

模型生成的文字位于对话区；可信系统审批使用独立固定布局和类型化字段。模型文本不得绘制成“系统已批准”，日志/模型输出中的 ANSI、OSC（含剪贴板/链接控制序列）必须过滤。

### 首次启动

1. 本地会话先启动，显示环境和“未配置模型”；允许跳过向导进入系统状态页。
2. 选择语言/键盘、检查时间、查看网络；没有网络也能继续浏览/配置。
3. 选择协议/服务地址/模型，单独输入密钥或选择凭据引用。密钥字段不进入对话、历史或普通审计。
4. 分阶段测试 DNS → TCP → TLS/时钟/CA → 认证 → 简短模型回复 → 工具能力；支持中断。网络调用与可能计费在测试前说明。
5. 明确选择“仅本次会话”或已解锁且受支持的持久存储，再应用。存储未就绪时不伪装已保存。
6. 返回主界面即可聊天；以后密钥失效仍可通过同一设置页修复。

### 自然语言与表单一致

“把 DNS 改为 X” → Agent 形成候选修改 → 展示与设置页相同的当前值/候选值/影响范围 → Broker验证 → 用户确认 → 应用/读回/结果。
设置页直接选 X → 同一候选修改链路。Agent 不需要看到 Wi-Fi 密码或 API Key；通过本地秘密输入事件获得引用。
查询、解释与建议可由 Agent 承担；真实值由系统后端返回，不能把模型估计作为已生效状态。

### 网络修改示例

先识别接口和当前连接，创建有截止时间的恢复点；显示将影响模型连接；确认后应用并验证地址、路由、DNS及选定探测目标。用户在本地确认保留，否则到期恢复。恢复计时器由后端持有，UI/模型退出不能取消它。无线环境或设备消失时恢复可能失败，应显示真实结果，不能承诺任意网络操作可逆。

## 5. 架构建议与复用边界

```text
非特权 Vita 会话（TUI / 行式降级）
  ├─ Talos Runtime：意图、对话、工具编排
  ├─ 本地设置/状态控制器：无需模型
  └─ 统一类型化能力客户端
          ↓ 本地认证 IPC / peer identity / 请求限额
    Vita Broker + 配置事务服务
      ├─ 风险/目标校验、确认凭证、审计、超时/恢复
      ├─ 只读 Linux facts / netlink
      └─ 网络、时间、服务、存储等受控适配器

PID1/监督器独立管理会话、Broker及所需守护服务
独立本地恢复入口不依赖上述模型、配置或 UI 正常启动
```

这不是要求第一版新建多个守护进程：先明确接口和失效边界，低风险只读能力可在非特权进程内；需特权、事务和独立恢复时再落实进程拆分。

| 路线 | 优点 | 问题 | 建议 |
| --- | --- | --- | --- |
| 直接运行 Talos CLI/TUI | 最快呈现已有聊天体验 | 违反既定嵌入边界，OS生命周期/设置权限缺位 | 不采用为产品主界面 |
| Vita 自有 ratatui/crossterm 界面 + SDK | 可控、Rust、离线设置与审批统一 | 需实现输入/布局/任务状态与回归 | 首选验证方向，尚未最终选型 |
| 提取上游可复用 UI 组件 | 减少重复的 Markdown/工具卡片实现 | 当前 Tui 耦合 conversation/core、Git状态等；需公共接口/依赖预算 | 逐件评估，不把内部模块当稳定 API |
| 最小图形终端承载同一 TUI | 中文字体/IME、尺寸事件更有基础 | 增加显示、输入、图形依赖和驱动需求 | 作为实体机中文体验候选 |
| 完整 Web/桌面设置中心 | 丰富控件与可访问性生态 | 当前 Live 镜像体积、服务面、运行时复杂度更高 | 后续共享相同能力 API，不作为首步 |

Rust-first不要求重写成熟网络认证或服务管理器。NetworkManager的D-Bus接口已有配置与checkpoint回滚机制，可通过 Rust zbus 访问，但采用它意味着显式评估 D-Bus、守护进程、无线后端、体积、许可证与所选 init 的兼容性。当前 rtnetlink 静态VM设置无法自然扩展为完整 Wi-Fi 管理。

hostname1/timedate1 等 systemd API 只能在相应服务存在时使用；不能因为宿主机有就假设 Vita 有。服务控制需要与最终 Rust/Dinit/Finit 选择解耦的能力协议；不能建立一组 shell 命令模板作为正常路径。

## 6. 配置、秘密与应用事务

### 四类数据分开

- **系统配置**：设备/网络/时间/服务；有主机适用范围、特权和依赖关系。
- **用户偏好**：主题、语言、键位、会话选择；通常不需 root。
- **模型/Agent配置**：provider、模型、能力、策略；权限上限不能被用户配置突破。
- **秘密**：API key、Wi-Fi口令、私钥；以引用存储，不能随配置导出或模型上下文流转。

推荐字段：schema_version、revision、scope、source、desired、observed、apply_status、requires_restart、secret_ref（需要时）。先定义版本迁移和未知字段处理；不要把 UI 表单数据结构直接作为永久格式。

### 分层与跨机器可携带性

优先级建议：系统受保护默认值 → 用户已信任的持久配置 → 明确启用的设备配置 → 当前会话覆盖。安全硬约束独立于优先级、不可覆盖。所有设置显示来源和生效范围。
USB换机器后，主题/模型偏好通常可携带；网卡名、磁盘路径、GPU/电源配置不可盲目重放。使用稳定身份、硬件匹配和重新确认；MAC也不是万能可信身份，可能随机化或伪造。

只读 rootfs 保持只读；运行态在 /run，持久配置在已授权用户数据域。系统服务使用受控生成/投影配置，不能为了设置页把整个 /etc 改为可写。P1用户镜像、P3系统资产和Talos数据遵循ADR-0009，不新增分区布局决定。

### 应用状态机

`读取(revision) → 编辑草稿 → schema/语义/能力校验 → 计划与差异 → 风险确认 → apply → read-back验证 → 提交持久状态/保留恢复记录`。

应用顺序依赖后端：支持 prepare/commit 的走事务；不支持的记录补偿步骤和不可逆点。网络 checkpoint 有时间窗口；磁盘格式化不能假装有回滚。崩溃恢复要区分“已写入、未确认”和“未执行”，不自动重放危险动作。
并发修改用 revision 冲突检测；设备拔出、重启、模型断线、服务拒绝都产生结构化状态。用户点取消不代表已执行 OS 操作被撤销。

模型切换先测试候选、不自动携带旧会话内容到另一服务；在明确回合边界重建 provider/runtime，说明会话是否保留。失败保持旧配置可用；不能静默转移到另一个模型服务。

凭据建议第一阶段只放内存/会话运行区并提供清除；持久化需另做加密、解锁、自动锁定、导出、轮换和撤销设计。OS key store 在独立 Live OS里未必存在；加密USB也需应对已解锁时恶意进程/物理访问。遮罩字段不是秘密存储方案。

## 7. 权限与失败模式

| 操作 | 建议等级与门槛 |
| --- | --- |
| 展示系统状态 | 只读且有敏感字段过滤/输出限制 |
| 改主题/布局 | 用户本地、可撤销，通常无需提权 |
| 保存模型endpoint/更换key | 端点与秘密校验、明确确认、审计元数据；不得审计秘密本身 |
| 网络/DNS/路由、防火墙、系统时钟、重启服务 | 明确计划、目标与影响、确认、后端鉴权、结果审计；可行时恢复窗口 |
| 格式化、引导更新、凭据/身份管理 | 单独高风险能力、目标证据与显式确认，相关 VM/人工门槛不可绕过 |

后端验证 peer uid/session、能力名、目标身份、参数哈希、配置revision、确认有效期；批准与具体计划绑定，不能用“允许一次”授权未来任意参数。无头/断开时拒绝待确认操作，恢复入口另有认证策略。

UI仅能提交计划和确认；模型不能生成有效的用户确认事件。检查目标至执行之间再次核对身份，设备路径重用/热拔插时失效。审计记录动作/范围/结果/错误类别和脱敏差异，不记录API key、Wi-Fi密码、完整模型请求或未经授权聊天。

无需模型的失败路径：模型认证失败→本地设置；网络断开→本地网络面板；TUI渲染失败→行式客户端；会话崩溃→监督器有限重启；Broker故障→只读/不可操作状态；独立恢复需可信本地授权，不能回退到无认证root shell。
当前上游provider重定向问题仍未解决，连接测试和HTTPS初始URL校验不能代替 transport policy。

## 8. 终端与性能验收重点

- raw mode、alternate screen、bracketed paste、按键解码、Ctrl+C/EOF、异常退出恢复 termios；监督器处理无法由 Drop 清理的崩溃。
- 单一渲染者拥有终端；PID1日志、工具stderr、内核console不能与TUI混写，另设日志通道/面板和启动交接。
- 串口传的是字节；宿主resize不等于客体TIOCSWINSZ/SIGWINCH。验证明确的尺寸协商或固定布局回退，限制终端探测等待。
- 中文、组合字符、宽字符、长行、粘贴、多字节分片；显示中文字形与输入法是两个不同问题。
- 80×24及更小窗口的降级、单色/低色终端、无鼠标、英文救援文字；ASCII不能当完整中文体验验收。
- 模型慢/不可用不阻塞设置；流式事件合并、日志环形缓冲、历史分页、受限粘贴/输入，避免无界队列和后台任务。
- 测量启动至可交互、输入延迟、空闲CPU、RSS、日志/历史增长及取消延迟。建议原型目标输入反馈p95<100ms、待机无忙循环；这是待校准目标，未测量、不作当前性能承诺。
- 桌面终端连接VM、QEMU GTK串口、UEFI/BIOS、真实 Linux VT分别验收；截图测试不能替代按键/进程/回滚行为测试。
